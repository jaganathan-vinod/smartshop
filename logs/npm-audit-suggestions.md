## Safer alternatives if a force upgrade would break things

### React Router v6 — stay on 6.x temporarily

If a v7 migration is not ready:

1. **Mitigate open redirects in app code** (works on v6 until you upgrade):
   - Centralize “safe internal redirect” helper: allow only same-origin relative paths (e.g. must start with `/`, reject `\`, `//`, `://`, encoded bypasses).
   - Use it for `LoginPage` (`state.from?.pathname`), `Navigate to={...}`, and any user-influenced `navigate(...)`.
   - Today, `Protected` stores full `location` in state; normalize to `{ pathname, search }` and validate `pathname` before redirect.

2. **SSR advisory:** No change required for SmartShop’s SPA; skipping v7 solely for `deserializeErrors` is reasonable.

3. **When ready:** Move to **`react-router-dom@^7.18.4`** with the [v6 → v7 upgrade guide](https://reactrouter.com/upgrading/v6) (React 18.3 is already in use; v7 supports it).

`npm audit fix --force` alone is a poor substitute for (1) + a planned v7 bump.

---

### CDK / infra esbuild — avoid breaking synth

If `esbuild@0.28.2` causes CDK issues:

1. **Try bumping only the direct dep** in `infra/package.json` first (no repo-wide override).

2. **If direct `esbuild` is redundant:** Confirm whether `infra` needs an explicit `esbuild` devDependency or if `aws-cdk-lib` / `aws-cdk` already satisfies bundling; removing an unused direct dep can let the lockfile use the newer transitive esbuild (verify with synth).

3. **Root `overrides` (last resort):** Single override `"esbuild": "^0.28.2"` after confirming `cdk synth` and tests — only if infra bump alone leaves a nested 0.24.2.

4. **Risk acceptance (documented):** If synth requires 0.24.x temporarily, document that production **does not** run esbuild’s dev server; restrict CI networks and do not expose esbuild serve on `0.0.0.0`. Revisit on the next CDK/esbuild alignment.

---

### `@cursor/sdk` / undici — no force fix

1. **Upstream:** Upgrade `@cursor/sdk` when releases fix the chain; subscribe to SDK release notes.

2. **Operational:** Run `audit:agent` / `pr-audit-agent.ts` only in trusted CI or locally; limit egress if paranoid about malicious HTTP targets.

3. **Substitutes (if SDK lag is unacceptable):** Reimplement the script with **`gh` CLI** or GitHub REST for PR checks — drops `@connectrpc/connect-node` and nested `undici` from the tree entirely (feature parity depends on what you use from `Agent.prompt`).

4. **Do not** force `undici@6.x` under `@connectrpc/connect-node` without SDK vendor confirmation.
