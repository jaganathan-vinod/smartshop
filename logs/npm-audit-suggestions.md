## If you want to avoid `--force` / major upgrades

### React Router v7 not ready

**Mitigate open redirect without v7** (defense in depth until **7.18.4+**):

- Add a small **`isSafeInternalPath(path)`** helper: allow only paths starting with a single `/`, reject `//`, `\`, `http:`, etc., and normalize or reject odd encodings.
- Use it for **`Navigate`** / **`navigate`** targets from **`location.state`** (`LoginPage`, any `state.from?.pathname`).
- Keep **`Protected`** passing **`from: location`** but only consume **`from.pathname`** after validation (not full URL objects from untrusted input).

**SSR hydration CVE:** No change required for architecture today (client-only Vite app); upgrading still recommended for advisory closure and future SSR.

**Safer routing alternatives (only if leaving React Router):** Large churn for this codebase (`App.tsx`, many pages). Not recommended vs. a focused v7 migration or interim path validation.

---

### CDK / esbuild major concern

You do **not** need a separate esbuild major for “CDK compatibility” if you **align infra with 0.28.2** already used elsewhere:

- Prefer **declared bump in `infra/package.json`** over `npm audit fix --force`.
- If `NodejsFunction` fails after bump, check [AWS CDK esbuild guidance](https://docs.aws.amazon.com/cdk/api/v2/docs/aws-cdk-lib.aws_lambda_nodejs-readme.html) for your CDK version (**2.262.x**); pin to the newest **0.25+** that synth accepts rather than staying on **0.24.2**.

**Alternative bundling (heavy):** Custom Lambda bundling (Docker, `esbuild` via CLI in CI only) — only if CDK and 0.28.2 conflict; unlikely on current stack.

---

### `@cursor/sdk` / undici

**Safer alternatives to forcing undici:**

- **Optional CI job** — Install/run `audit:agent` only in a workflow that needs it; production deploy graph stays unchanged.
- **Replace SDK** — Implement the same `Agent.prompt` flow via documented HTTP/gRPC once Cursor exposes a stable non-SDK path (more maintenance).
- **Suppress with rationale** — Record in security notes: dev-only, trusted endpoints, no fix available; re-audit monthly.

Do **not** use `npm audit fix --force` on the root for this chain; it will not resolve these entries and may disturb unrelated packages.
