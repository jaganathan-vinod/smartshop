## Safer alternatives if a force upgrade would break CDK or React Router v6

### React Router — stay on v6 for now

If v7 migration is not scheduled:

- **Compensating controls (app-level):**
  - Treat **`Navigate` / `navigate(to)`** targets as untrusted when derived from location state, query params, or storage (e.g. `LoginPage` `state.from?.pathname`, chat redirect helpers). Allow only **same-origin relative paths** matching a strict pattern (e.g. `^/[a-zA-Z0-9/._-]*$`), reject `\`, `//`, `:`, and encoded variants.
  - Keep using **literal or app-built paths** in `Link` (current code is mostly this way).
- **SSR advisory:** No change required for hydration CVE if you remain a Vite SPA; still plan v7+ for the open-redirect fix.
- **Do not** rely on `npm audit fix --force` alone without a v7 migration pass — breaking route APIs and bundler assumptions is likely.

### esbuild — avoid a risky CDK break

If `0.28.x` causes CDK synth or Lambda bundling failures:

- **Accept residual audit noise temporarily** with documented rationale: SmartShop does not run the esbuild **dev server** in prod; CDK uses `esbuild.build()` for asset bundling ([GHSA-67mh-4wv8-2f99](https://github.com/advisories/GHSA-67mh-4wv8-2f99)).
- **Try a minimal override** only under `infra` via root **`overrides`** pinning `esbuild` to `0.28.2` while keeping `aws-cdk-lib@^2.262.1`; many CDK versions tolerate newer esbuild, but **verify with `cdk synth`** before merging.
- **Alternative bundler for assistant only:** If infra must stay on `0.24.2`, bundle the assistant with **Node 22 + `tsx`/tsc** or a separate pinned esbuild in `@smartshop/assistant` only (isolates CDK’s tree from assistant bundling). That does not remove the infra advisory until infra’s esbuild is upgraded.

### `@cursor/sdk` / undici — no clean bump

- **Safest:** Keep `@cursor/sdk` dev-only; run audit agent in locked-down CI; upgrade SDK when maintainers ship fixed Connect/undici.
- **Experimental:** Root **`overrides`** for `undici@^6.28.0` — lowest risk if you validate only the PR audit script, not production services.
- **Alternative tooling:** Replace `@cursor/sdk` in `pr-audit-agent.ts` with direct HTTPS calls to Cursor’s documented API (if you control fetch and can use Node’s built-in `fetch` on Node 20+), dropping the Connect/undici chain — only worth it if overrides fail and audit noise blocks merges.
