## If a major / `--force` upgrade would break things

### React Router v6 — stay on v6 for now

Audit fixed versions are **≥7.18.0** only; there is **no semver-minor fix** inside v6 in this report.

**Safer mitigations while staying on v6:**

- **Open redirect (GHSA-wrjc-x8rr-h8h6):** SmartShop mostly uses **fixed internal paths** in `Link` / `navigate`. Keep it that way:
  - Never pass **user/API-controlled** strings into `to` or `navigate(...)`.
  - Centralize external URLs through a helper that allows only `http(s):` and rejects `\`, `//`, and scheme tricks.
- **Constructor injection / SSR (GHSA-337j-9hxr-rhxg):** **Deprioritize** — no SSR hydration path in `web/src/main.tsx` / `App.tsx`.
- **Process:** Document accepted risk for v6 until a v7 migration sprint; re-run audit after `react-router-dom@7.18.4`.

**Not a durable substitute:** `npm audit fix --force` without a v7 migration plan — likely breaks tests and routing.

### esbuild — avoid a big jump if CDK complains

**Safer path than jumping straight to 0.28.x:**

1. Try the **smallest patched 0.x** above `0.24.2` that `cdk synth` accepts (advisory: `<=0.24.2` vulnerable).
2. If CDK fails, align with **the esbuild version `aws-cdk-lib@^2.177.0` documents/supports** rather than forcing 0.28.2.
3. **Operational mitigation:** Do not run esbuild **`serve`** in CI or locally for this repo (you do not today). Keep **Vite dev** bound to localhost; the esbuild dev-server CVE is separate from Vite’s own dev server surface (Vite bundles its own esbuild — not flagged in this audit snapshot; optional separate `npm audit -w @smartshop/web`).

**If explicit `esbuild` in `infra` is redundant:** After checking CDK still bundles Lambdas, removing the direct devDependency and relying on CDK’s transitive esbuild can reduce duplicate vulnerable copies — only after confirming `cdk synth` still resolves a patched version.

### `@cursor/sdk` / undici — avoid `--force` on the SDK

**Safer alternatives:**

- **Root `overrides` for `undici` only** (narrower blast radius than force-upgrading Connect/SDK majors).
- **Scope:** Run `audit:agent` only on trusted networks; optional dedicated CI job with restricted egress.
- **Last resort:** Replace SDK usage in `pr-audit-agent.ts` with direct HTTP to Cursor APIs (more maintenance, drops transitive Connect/undici if nothing else needs the SDK).
