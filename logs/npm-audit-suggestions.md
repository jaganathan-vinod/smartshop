## Recommended actions (by priority)

### 1. `react-router-dom` / `react-router` (production — prioritize)

**Advisories:** open redirect via backslash in `<Link>` / `useNavigate` ([GHSA-wrjc-x8rr-h8h6](https://github.com/advisories/GHSA-wrjc-x8rr-h8h6)); SSR `deserializeErrors` constructor injection ([GHSA-337j-9hxr-rhxg](https://github.com/advisories/GHSA-337j-9hxr-rhxg)).

**Bump:** npm audit suggests **`react-router-dom@7.18.4`** — treated as a **major** jump from v6 (`isSemVerMajor: true`). Update **`web/package.json`** (direct dep); `react-router` follows transitively.

**SSR note:** The app is a **client-only** Vite SPA (`createRoot` in `web/src/main.tsx`), so the **SSR hydration / `deserializeErrors`** issue does **not** apply today. The **open-redirect** issue still applies to client-side navigation.

**App-specific exposure:** `LoginPage` uses `Navigate` / `navigate` with `state.from?.pathname` (post-login redirect). That pattern plus the backslash bypass increases interest in either upgrading or hardening redirects.

**Suggested upgrade path (when you choose to apply):**

```bash
npm install react-router-dom@^7.18.4 -w @smartshop/web
```

Then run web tests and a quick smoke pass on auth redirects, category/product links, and checkout → order detail navigation. Review [React Router v7 upgrade notes](https://reactrouter.com/upgrading/v6) (many v6 apps need only dependency and import tweaks).

**Major / `--force`:** A normal **`npm install`** with an explicit **7.18.4** range should suffice; **`npm audit fix --force`** is **not** required and is riskier in a monorepo because it can rewrite unrelated packages.

## Safer alternatives (avoid `--force` / major breakage)

### If React Router v7 is too disruptive now

There is **no patched 6.x** in the advisory ranges (**`<7.18.0`** still includes **6.30.6**). Staying on v6 means **mitigations**, not audit green:

- **Centralize redirects:** One helper that allows only **relative** paths starting with `/`, rejects `\`, `//`, `http:`, and encoded bypasses; use it for `Navigate`, `navigate()`, and any `to={...}` built from API/user input.
- **Harden login return URL:** Replace raw `state.from?.pathname` with a validated in-app path (or ignore external paths and default to `/`).
- **Links:** Product/order IDs in paths are likely safe if IDs are constrained; category slugs should be validated against known slugs if they ever come from untrusted input.
- **Plan v7:** Schedule **`react-router-dom@^7.18.4`** when you can run the migration guide and regression tests — that is the durable fix.

`deserializeErrors` mitigations are **N/A** unless you add SSR later.

### If bumping infra `esbuild` breaks CDK

- **Drop the direct pin** if it was only to silence version skew: **`NodejsFunction`** uses esbuild via **`aws-cdk-lib`**’s own dependency — run synth/deploy without a separate infra `esbuild` line and see if CDK’s bundled version is already **`>0.24.2`**.
- **Minimal bump:** Try **`^0.25.x`** first if **`^0.28.2`** causes CDK friction (advisory needs **`>0.24.2`**, not necessarily 0.28).
- **Root `overrides`:** `"esbuild": "^0.28.2"` only after **`cdk synth`** and Lambda bundle tests pass — CDK pin mismatches are the usual failure mode.
- **Operational:** Do not expose **`esbuild --serve`** or custom serve middleware on untrusted networks (aligns with the advisory’s dev-server threat model).

### If `undici` override breaks `@cursor/sdk`

- **No override**; wait for **`@cursor/sdk`** / Connect RPC updates.
- **Isolate:** Separate optional workspace or one-off job for the audit agent so production install graphs stay minimal.
- **Last resort:** Replace `@cursor/sdk` usage in `scripts/pr-audit-agent.ts` with a maintained HTTP client you control (only if SDK churn blocks security policy).

## Suggested remediation order

1. **`web`:** Plan **`react-router-dom@^7.18.4`** (or v6 mitigations + documented exception until migration).
2. **`infra`:** Targeted **`esbuild@^0.28.2`** (or remove redundant pin / minimal **0.25+**) + **`cdk synth`** / deploy dry run.
3. **Root:** Monitor **`@cursor/sdk`**; avoid **`undici` overrides** unless you can test the audit agent; treat as **dev-only** risk until upstream fixes.

After changes (when you apply them), re-run **`npm audit`** at the repo root and confirm **`react-router`** and **`esbuild`** clear; expect **`@cursor/sdk` / undici** may remain until the vendor chain updates.
