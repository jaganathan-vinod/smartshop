## Recommended bumps (by package)

### 1. `react-router-dom` (+ transitive `react-router`) — **priority: production**

- **Workspace:** `web/package.json` (`^6.28.0` today).
- **Audit fix:** `react-router-dom@7.18.4` — **semver major** (`isSemVerMajor: true`).
- **Command shape (when you choose to upgrade):** bump in `web`, then `npm install` at repo root; run `web` tests and a quick smoke of routes/auth redirects.
- **`npm audit fix --force`:** would jump to v7; treat as a **planned migration**, not a silent CI fix.

**If you stay on v6 for now (mitigations):**

- No patched 6.x in the advisory ranges shown (`<7.18.0`); staying on 6.x is **accept residual risk** + harden navigation.
- Avoid passing **user-controlled** strings to `<Link to={...}>`, `useNavigate(...)`, or `<Navigate to={...}>` without validation.
- **`LoginPage` / `Protected`:** `state.from?.pathname` after login is a classic redirect surface — allow only same-origin relative paths (e.g. must start with `/`, reject `\`, `//`, and `:` schemes).
- SSR hydration advisory ([GHSA-337j-9hxr-rhxg](https://github.com/advisories/GHSA-337j-9hxr-rhxg)): **not applicable** until you add React Router SSR/data APIs.

**Safer alternative to a forced v7 jump:**

- Short term: **v6 + redirect allowlist** (above).
- Medium term: **React Router 7.18.4** following [v7 upgrade guide](https://reactrouter.com/upgrading/v6) (often workable from v6 with incremental changes; still test Amplify auth flows and all routes).

### 2. `esbuild` — **priority: build hygiene**

- **Workspace:** `infra/package.json` (`^0.24.2`, direct devDep; audit node `infra/node_modules/esbuild`).
- **Audit fix:** `esbuild@0.28.2` — **semver major**.
- **Not required for CDK synth/deploy by itself:** `aws-cdk-lib` bundles its own esbuild for Lambda asset bundling; upgrading **infra’s direct** `esbuild` does not automatically patch CDK’s nested copy (run audit again after CDK bumps if that tree is flagged separately).

**Safer alternatives if a major bump breaks scripts:**

- If nothing in `infra` imports esbuild (currently **no** `infra/lib` usage), consider **removing** the unused direct devDependency and declaring esbuild only where `bundle.mjs` runs (e.g. `services/assistant` or a root script devDep) at **≥0.25.0** (patched for [GHSA-67mh-4wv8-2f99](https://github.com/advisories/GHSA-67mh-4wv8-2f99)).
- **Operational:** never run esbuild **`serve`** on `0.0.0.0` in shared CI; keep Vite dev on localhost.
- **Do not** use root `overrides` to force esbuild globally without running `infra` tests, `web` build, and assistant bundle — multiple majors can coexist in a monorepo and overrides can break CDK’s expected version.
