## Safer alternatives if a force upgrade would break things

### React Router v6 — avoid jumping to v7 immediately

You cannot patch in-place on v6 for these advisories (affected range **`>=6.0.0 <7.18.0`**). Mitigations while staying on 6.x:

1. **Accept documented risk** for a controlled e-commerce MVP where routes are app-defined (your `Link`/`navigate` usage is mostly static paths and `useParams` — low open-redirect risk unless you later add user-controlled URLs).
2. **Coding standards:** Never pass query/body/user input into `to=` or `navigate()` without validating same-origin relative paths (reject `\`, `//`, and encoded bypasses).
3. **Defense in depth:** CSP and avoiding reflected navigation targets in chat/search features.
4. **SSR advisory:** No action needed — no React Router SSR/hydration in this repo.

When ready, **7.18.4+** is the proper fix; v7 supports a gradual upgrade from v6 patterns.

### CDK / infra `esbuild` — avoid risky `--force` or blind major jumps

1. **Minimal fix:** Set infra `esbuild` to **`^0.25.0`** or **`^0.28.2`** in `infra/package.json` only (targeted bump, not repo-wide `audit fix --force`).
2. **Dedupe:** After bump, confirm lock no longer nests `infra/node_modules/esbuild@0.24.2` (optional `overrides` only if hoisting fights you — usually unnecessary in npm workspaces).
3. **If CDK bundling breaks on newer esbuild:** Temporarily use CDK **`bundling.forceDockerBundling: true`** on `NodejsFunction` for deploy (slower, no esbuild version tie-in) — escape hatch, not default.
4. **Process mitigation:** Do not run `esbuild --serve` on untrusted networks; CDK synth uses build-only API ([GHSA-67mh-4wv8-2f99](https://github.com/advisories/GHSA-67mh-4wv8-2f99)).

### `@cursor/sdk` / undici — avoid forcing undici 6 without testing

1. **Lowest risk:** Keep **`@cursor/sdk` dev-only**; run `audit:agent` only in trusted CI with outbound restrictions; do not promote it to runtime workspaces.
2. **Reduce dependency:** If SDK usage stays minimal (`Agent`, `CursorAgentError` in `scripts/pr-audit-agent.ts`), consider replacing with **direct HTTPS calls** to the Cursor API and **dropping `@cursor/sdk`** — removes the entire undici/connect-node chain from the tree (tradeoff: maintain HTTP client yourself).
3. **Override (last resort):** Root `"overrides": { "undici": "^6.28.0" }` — may break `@connectrpc/connect-node@1.7.0` (built against undici 5.x). Only use with a dedicated test of the agent script; prefer upstream fix.
